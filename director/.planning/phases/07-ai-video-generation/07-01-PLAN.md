     b. Set node status to 'generating'
     c. Fetch the source asset_set_item to get the asset URL (reference image for the current node)
     d. Fetch completed prior nodes (same asset_set_id, position < current, status = 'completed', ordered by position DESC, limit 2) to use their thumbnailUrl/videoUrl as reference images for visual consistency (GEN-02)
     e. Fetch the Director's Brief (director_cuts table) for the node's project_id to extract mood, palette, cinematography, theme
     f. Build a video generation prompt combining: node title, description, narrative context (emotionalTone, transitionFromPrevious, durationHint), Director's Brief visual style, and reference context
     g. Generate video:
        - If REPLICATE_API_TOKEN is set: use Replicate API with `minimax/video-01-live` model (image-to-video). Input: `prompt` (the built prompt), `prompt_image_url` (the node's asset URL), `prompt_optimizer` set to true. Handle output as array of URLs or FileOutput objects (same pattern as gap-fill route).
        - If no API token: mock mode returning `https://placehold.co/1024x576/1a1a1a/ff9064?text=Video+Node+{position}` and log mock message
     h. Insert a new asset_set_item for the generated video:
        - asset_set_id from the node
        - name: `Video: {node.title}`
        - type: 'video'
        - url: the generated video URL
        - thumbnail_url: node's existing thumbnail_url (still image)
        - metadata: `{ source: 'video-generation', nodeId: node.id, projectId: node.projectId, generationPrompt: prompt, referenceNodes: [prior node IDs] }`
        - position: node.position (same position as source node for traceability)
     i. Update pipeline_node: set status to 'completed', video_url to the generated URL, updated_at
     j. Return the updated PipelineNode
   - Error handling: on any failure after 'generating' was set, revert status to 'error' with error message in metadata, return 500
