<objective>
Build the gap-fill data layer: extend gap status lifecycle, create the fill API route with Replicate image generation (with deterministic mock as default dev mode), insert generated assets into the asset library with gap-fill tag, and create bridge pipeline nodes at the correct position.

Purpose: This is the backend engine for gap filling. When a user clicks "Auto-Fill" on a detected gap, the system generates a bridge scene image, stores it as an asset, inserts a bridge node into the pipeline between the source and target nodes, and marks the gap as filled.

Output: SQL migration, updated types, fill API route, updated gap store with fillGap action
</objective>

    **1. Create SQL migration `supabase/migrations/005_gap_fill.sql`:**
    - ALTER the pipeline_gaps table to drop the existing CHECK constraint on `status` and recreate it with the expanded set: `('detected', 'accepted', 'dismissed', 'fill-requested', 'generating', 'filled')`.
    - Use: `ALTER TABLE pipeline_gaps DROP CONSTRAINT IF EXISTS pipeline_gaps_status_check; ALTER TABLE pipeline_gaps ADD CONSTRAINT pipeline_gaps_status_check CHECK (status IN ('detected', 'accepted', 'dismissed', 'fill-requested', 'generating', 'filled'));`
    - Add a `fill_node_id` column (UUID, nullable, FK to pipeline_nodes.id ON DELETE SET NULL) to track which bridge node was created for each filled gap.

    **2. Update `src/lib/types/pipeline-gap.ts`:**
    - Extend `GapStatus` to: `'detected' | 'accepted' | 'dismissed' | 'fill-requested' | 'generating' | 'filled'`
    - Add optional `fillNodeId?: string` to `PipelineGap` interface.

    **3. Create `src/app/api/pipeline-gaps/fill/route.ts`:**
    - POST endpoint accepting `{ gapId: string }` in body.
    - Follow the exact Supabase server client pattern from the analyze route (createServerClient with async cookies).
    - Include `mapRowToGap`, `mapRowToNode` helpers (same pattern as other routes). Add `fillNodeId: (row.fill_node_id as string) ?? null` to mapRowToGap.

    **Fill logic (sequential steps):**

    a. **Fetch gap** from pipeline_gaps by gapId. Validate status is 'fill-requested'. Return 400 if not.

    b. **Set gap status to 'generating'** immediately (UPDATE pipeline_gaps SET status='generating').

    c. **Fetch source and target pipeline_nodes** by gap's sourceNodeId and targetNodeId.

    d. **Fetch Director's Brief** from director_cuts where project_id = gap.projectId, limit 1.

    e. **Build image generation prompt** from:
       - Gap's `suggestion` field (primary direction)
       - Gap's `gapType` ('visual' = focus on visual bridging, 'narrative' = focus on story transition)
       - Director's Brief: `storyline.theme`, `visualStyle.mood`, `visualStyle.colorPalette` (join as comma-separated), first `cinematographyRefs` entry
       - Source node's `narrativeContext.emotionalTone` and target node's `narrativeContext.emotionalTone`
       - Format: `"Bridge scene: {gap.suggestion}. Style: {brief.visualStyle.mood} mood, {palette} palette, {cinematography}. Theme: {brief.storyline.theme}. Transition from {sourceTone} to {targetTone} emotional tone."`

    f. **Generate image (dual-mode, matching Phase 5 pattern):**
       - If `REPLICATE_API_TOKEN` env var exists: call Replicate API using the `replicate` npm package. Use model `black-forest-labs/flux-schnell` (fast, good quality). Pass the built prompt. Await the output URL.
       - If no `REPLICATE_API_TOKEN` (default dev mode): use a deterministic mock that returns a placeholder URL string `https://placehold.co/1024x576/1a1a1a/ff9064?text=Bridge+Scene` and logs `[gap-fill] Mock mode: skipping image generation for gap {gapId}`.

    g. **Insert asset_set_item** into the same asset_set_id as the gap:
       - `name`: `"Bridge: {sourceNode.title} -> {targetNode.title}"`
       - `type`: `'image'`
       - `url`: the generated image URL (from Replicate or mock)
       - `thumbnail_url`: same as url
       - `metadata`: `{ source: 'gap-fill', gapId: gap.id, gapType: gap.gapType, generationPrompt: builtPrompt }`
       - `position`: sourceNode.position + 1 (will be between source and target)

    h. **Shift existing asset_set_items positions** that are >= sourceNode.position + 1 in the same asset_set_id by incrementing their position by 1 (to make room). Use: `UPDATE asset_set_items SET position = position + 1 WHERE asset_set_id = ? AND position >= ? AND id != newItemId`.

    i. **Shift existing pipeline_nodes positions** that are > sourceNode.position in the same asset_set_id by incrementing their position by 1. Use: `UPDATE pipeline_nodes SET position = position + 1 WHERE asset_set_id = ? AND position > sourceNode.position`.

    j. **Insert bridge pipeline_node:**
       - `project_id`: gap.projectId
       - `asset_set_id`: gap.assetSetId
       - `asset_item_id`: the new asset_set_item.id from step g
       - `position`: sourceNode.position + 1
       - `title`: `"Bridge: {sourceNode.title} -> {targetNode.title}"`
       - `description`: gap.suggestion
       - `status`: `'ready'`
       - `narrative_context`: `{ emotionalTone: "transitional", transitionFromPrevious: "dissolve", durationHint: "2-3 seconds" }`
       - `thumbnail_url`: the generated image URL
       - `metadata`: `{ source: 'gap-fill', gapId: gap.id }`

    k. **Update gap status to 'filled'** and set `fill_node_id` to the new pipeline_node's id.

    l. **Return** the updated PipelineGap object (mapped to camelCase).

    **Error handling:** If any step after 'generating' status fails, catch the error, set gap status back to 'fill-requested', and return 500 with error message. This ensures retryability.
